# 022 — Data-Driven Terrain: Landscapes Without C++

## Plain-English Summary

Until now, SAGE's two landscapes (Stunt City and Echo Island) were **written in C++**: every mountain, lake and ring road was a hard-coded coordinate in `world.cpp`, and grass placement was tied to those same roads. Making a third game meant editing engine code, which broke SAGE's promise of building games with JSON + Lua only.

Now a scene describes its own landscape, the way a recipe lists ingredients: "start with gentle hills, make it an island, add a 46 m mountain here, carve a lake there, flatten a spot for the village, run a road up to it, paint sand → meadow → forest → snow". The engine follows the recipe.

## Technical Deep Dive

**One height function, three consumers.** `World::sampleTerrain` evaluates the spec. The GPU mesh, Jolt `HeightFieldShape` and grass scatter all call it, so the visuals, physics and gameplay queries can't disagree. This is the same lesson as L002 (CPU and GPU must share exact formulas).

**Composition order:** `baseHeight + heightmap + FBM noise → island mask → features (in order)`. Ordered features make results predictable and let later features fix earlier ones (flatten the top of a peak). The four feature types cover most open-world layout needs:
* **peak:** `+height * (1 - smoothstep(0, r, d))^sharpness`
* **basin:** flatten toward the centre by `strength`, then subtract `depth` (lakes, craters)
* **flatten:** blend to an exact height between `innerRadius` and `radius` (town sites)
* **road:** distance-to-polyline with per-point heights, interpolated per segment, so roads can climb

**Materials:** up to 6 height-banded layers plus slope-based cliff and height-based snow, uploaded as 15 `vec4` uniforms (`uniform4fv`), with the existing procedural micro-detail and bump noise on top. `biomeId` from `sampleTerrain` is the layer index, so Lua can pick footstep sounds and gameplay by surface.

**Rebuilds:** `TerrainSettings::revision` increments on every scene load and on terrain changes from Lua. The renderer and physics compare revisions instead of a few cached numbers. Previously, hot-reloading a scene with different terrain numbers didn't rebuild the mesh or grass.

**Validation:** every value is type-checked, and errors name the file plus the JSON path (`terrain.features[2].points`). Unknown keys produce a warning, which catches typos like `octavs`. Colours above 1 get a "did you use 0..255?" warning. An invalid block falls back to flat terrain instead of crashing.

**Legacy presets are untouched:** mode 0/1 code paths are unchanged. Old and new builds produce identical terrain triangle counts (31,824 / 25,718), grass counts (32,525 / 54,000) and colliders. Screenshot diffs from identical cameras differ in only ~0.1% of pixels, all on moving vehicles and wind-swayed grass.

## How SAGE Uses This
* **New games:** write a `"terrain"` block (reference: [`docs/terrain.md`](../terrain.md)); no C++ needed.
* **Demos:** `scenes/terrain_demo.json` (procedural island: mountain, lake, village plateau, climbing road, snow) and `scenes/heightmap_demo.json` (16-bit PNG river canyon, generated by `tools/generate_demo_heightmap.py`), previewed with the `terrain_demo` resource.
* **Export:** `SceneLoader::saveToFile` now writes the terrain block back exactly as authored; before, exported scenes lost their terrain.

## Lessons & Gotchas
* **Shallow-water seams:** culling seabed triangles (`hideBelowHeight`) close to the surface makes a stair-step seam, because the water shader shades by depth. Keep it well below visible seabed.
* **Roads through hills** cut cliff-coloured walls. Route around peaks or give points heights.
* **Collider resolution:** the Jolt collider stays at 129×129 samples, so very fine heightmap detail is visual only. A future step is to scale the collider resolution with `halfSize`.

## Next steps
